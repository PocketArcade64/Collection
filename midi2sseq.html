midi2sseq / nitro composer

Converts a standard MIDI file into a Nintendo DS SSEQ sequence, the format Pokémon Diamond, Pearl, Platinum, HeartGold and SoulSilver use for music. Everything runs in this page; nothing is uploaded anywhere.

48 ticks per quarter 16 tracks max 1–240 BPM duration-encoded notes timbre comes from the game's SBNK + SWAR

1 · Source MIDI

Drop a .mid file here or press Enter to browse. Format 0 and format 1 both work.

2 · Instrument bank

Gen 4's sound cannot be synthesised from scratch: it lives in the game's own SBNK and SWAR. Extract sound_data.sdat from a ROM once with a NitroFS tool such as Tinke or ndstool, then load it here. Loading it is optional for making an SSEQ, but it lets this page list the real instrument indices instead of guessing, and lets you write the result straight back into the archive.

3 · Tracks and instrument mapping

One row per output SSEQ track. Instr is an index into the SBNK, not a General MIDI program: Gen 4's bank is not laid out like GM, so the starting guess is program number passed straight through and you are expected to correct it by ear.

4 · Conversion options

A quarter note is always 48 ticks and tempo caps at 240 BPM. Auto multiplies every tick value and divides BPM by the same power of two, so fast MIDI files stay in range and timing is unchanged.

The DS mixes 16 hardware channels across music and sound effects. Leaving a few free stops the engine from cutting your music off when a cry or menu blip plays. Notes over the cap are dropped quietest-first and counted in the report.

MIDI has no loop concept, so one is imposed. Marker mode looks for a marker or text meta event containing that word; if none exists it falls back to looping the whole sequence. Every track is padded to the same end tick before jumping, otherwise they drift apart on the second pass.

  Built against the Nitro Composer sequence command table. Notes carry their own duration, so there are no note-off events; time advances only through 0x80 waits, with note-wait switched off at the top of every track so chords stack. Track offsets in 0x93 and 0x94 are 24-bit and relative to the start of the sequence data, which is why the writer resolves labels in a second pass.
